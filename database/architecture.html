El diseño no cambió; cambió lo que lo hace cumplir. Las mismas capas y las mismas 80 tablas siguen ahí. Lo que aparece es todo lo que un archivo .sql no puede hacer: ejecutarse, probarse contra datos y avisar cuando algo se rompe.The design didn't change — what enforces it did. The same layers and the same 80 tables are still there. What's new is everything a .sql file can't do: run, be tested against data, and warn you when something breaks.

Antes y después, capa por capaBefore and after, layer by layer

Cada objeto del DDL tiene su contraparte en dbt. Pero silver ya no es una sola capa: el DDL la describía como tres trabajos a la vez — tipar, aplicar reglas de negocio y modelar — y dbt los separa en staging, intermediate y marts, cada uno con su propia responsabilidad y sus propios tests.Every DDL object has its dbt counterpart. But silver is no longer a single layer: the DDL described it as three jobs at once — typing, applying business rules and modeling — and dbt splits them into staging, intermediate and marts, each with its own responsibility and its own tests.

Una referencia que el motor entiendeA reference the engine understands

Antes · DDLBefore · DDLdatabase/schema/04_gold.sql
CREATE VIEW gold.rpt_01_ventas_diarias AS
SELECT
    p.date_key         AS fecha,
    eq.nombre_equipo   AS equipo,
    v.codigo_vendedor  AS vendedor,
    pr.categoria       AS linea_producto,
    SUM(p.importe_neto) AS monto_mxn
FROM silver.fact_pedido p
JOIN silver.dim_vendedor v  ON v.vendedor_key = p.vendedor_key
JOIN silver.dim_equipo eq   ON eq.equipo_key = v.equipo_key
JOIN silver.dim_producto pr ON pr.producto_key = p.producto_key
GROUP BY p.date_key, eq.nombre_equipo, v.codigo_vendedor, pr.categoria;
Después · dbtAfter · dbtmodels/gold/01_ventas_por_equipo/rpt_ventas_diarias.sql

    dv.equipo,

Un contrato en lugar de un comentarioA contract instead of a comment

Antes · DDLBefore · DDLdatabase/schema/04_gold.sql
COMMENT ON VIEW gold.rpt_01_ventas_diarias IS

  config:
    contract:
      enforced: true

  - name: fecha
    data_type: date
  - name: equipo
    data_type: varchar
  # ...
  - name: monto_mxn
    data_type: double
    data_tests:
    - not_null
    - dbt_utils.accepted_range:
        arguments:
          min_value: 0

En el DDL, lo que el dashboard esperaba vivía en un comentario: renombrar una columna lo rompía sin aviso. Con contract: enforced (los 19 reportes gold), dbt se niega a materializar el modelo si cambia una columna o un tipo, y el CI falla antes del merge.In the DDL, what the dashboard expected lived in a comment: renaming a column broke it silently. With contract: enforced (all 19 gold reports), dbt refuses to materialize the model if a column or type changes, and CI fails before the merge.

El DDL definía la tabla pero no cómo se llena. fct_pedido es incremental: cada corrida procesa solo los pedidos posteriores a la última fecha cargada. Verificado a mano: dos corridas sin datos nuevos no reprocesan nada, y un día nuevo inserta solo esas filas.The DDL defined the table but not how it gets filled. fct_pedido is incremental: each run only processes orders after the last loaded date. Checked by hand: two runs with no new data reprocess nothing, and a new day inserts only those rows.

Un hecho, seis reportesOne fact, six reports

fct_pedido es el hecho central: la misma venta, agregada de seis formas para seis dashboards. Con el grafo, el alcance de un cambio deja de ser una corazonada: 9 de los 19 reportes gold dependen de él, directa o indirectamente. Dos tests singulares lo custodian: que no pierda líneas respecto a staging y que las ventas diarias reconcilien con él.fct_pedido is the central fact: the same sale, aggregated six ways for six dashboards. With the graph, the blast radius of a change stops being a hunch: 9 of the 19 gold reports depend on it, directly or indirectly. Two singular tests guard it: that it never drops lines relative to staging, and that daily sales reconcile with it.

La puerta por la que pasa cada cambioThe gate every change goes through

Si un modelo, un test o un contrato falla, el PR queda en rojo antes del merge.Every pull request that touches warehouse/ runs the full pipeline against an ephemeral DuckDB — no credentials, no server.
